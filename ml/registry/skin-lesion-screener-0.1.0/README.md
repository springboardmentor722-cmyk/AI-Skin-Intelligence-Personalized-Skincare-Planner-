# skin-lesion-screener-0.1.0

A real, trained ResNet18-based classifier over the 8 real ISIC 2019 diagnostic
classes (AK, BCC, BKL, DF, MEL, NV, SCC, VASC), trained on
`training_dataset/raw/isic-2019/` (`training_dataset/MANIFEST.md` #3). Full
training pipeline: `ml/training/train_lesion_classifier.py`. Full metrics,
dataset composition, and the two disclaimers below: `metadata.json` in this
directory (generated by the training run, not hand-written).

## What this is — and isn't

**Is:** a dermatological lesion/condition classifier — the real output space
ISIC 2019 actually labels (melanoma, basal cell carcinoma, actinic keratosis,
...). Positioned as a future dermatologist-facing condition-report aid
(`docs/ARCHITECTURE.md`'s Dermatologist role, "Condition Reports" nav item —
not yet built; this artifact is not wired into any endpoint yet).

**Is not:** the app's consumer-facing "Concern Detector" / "Skin Type
Classifier" (`docs/AI_ML.md`'s model cards, ADR-007) — those operate over the
`skin_concerns` taxonomy (acne, hyperpigmentation, oiliness, ...), a
completely different label space. Training on ISIC's lesion categories and
calling it a cosmetic concern detector would be a real, confirmed dataset-task
mismatch (found and confirmed with the project owner before training,
`PROGRESS.md` 2026-07-23) — this model is never presented as that.

## Fairness gap — real, not silently worked around

`docs/AI_ML.md`'s fairness requirement is explicit: *"non-negotiable for a skin
product ... a per-tone accuracy gap > 5pp blocks release."* ISIC 2019's own
metadata (`ISIC_2019_Training_Metadata.csv`: `image, age_approx,
anatom_site_general, lesion_id, sex`) has **no skin-tone field at all** — no
Fitzpatrick scale, no Monk scale, nothing to slice by. This model cannot be
evaluated against that requirement with the data actually available, full
stop. It is **not release-ready** by this project's own standard until real
tone-annotated training/eval data exists — trained and documented here as a
real, working, honestly-limited artifact, not fabricated compliance.

## Not medical advice

Same disclaimer every AI-derived surface in this app already carries
(`AGENTS.md` §2 rule 8) — advisory only, never a diagnosis, and every
prediction's confidence must be shown alongside it, never hidden, whenever
this eventually gets wired into a real screen.

## Why it isn't wired into the backend yet

`ml/training/` deliberately has its own dependency set (torch/torchvision,
`ml/pyproject.toml`) — kept out of `backend/`'s own `pyproject.toml` so the
FastAPI API service doesn't carry ~1GB of deep-learning dependencies it never
needs to serve a request today. There is also no Condition Reports endpoint
or screen built yet for this to serve. Wiring it in for real (loading
`model.pt`, adding `torch` to `backend/`'s dependencies or serving via ONNX
Runtime instead, adding an `app/ai/` interface + a Dermatologist-role
endpoint) is real, separate future work — a deliberate scope boundary, not an
oversight.
