# Model registry (documented layout, M3-H)

Per `docs/AI_ML.md`'s "Serving & ops" section: trained artifacts are versioned here (or
in S3 for anything too large for the repo) as `{model}-{semver}/`, e.g.
`recommender-1.0.0/`. The active version for each model surface is a config value
(`AI_IMPL_*` env vars, `backend/app/core/config.py`), never a hardcoded path — the
same config-selected-implementation pattern ADR-007 already establishes for
stub/real switching.

## What's here

- **`skin-lesion-screener-0.1.0/`** (2026-07-23) — a real, trained ResNet18
  classifier over ISIC 2019's 8 real lesion categories. See that directory's own
  `README.md` for the two disclaimers that matter before touching it: it is
  *not* the app's consumer "Concern Detector" (a genuine dataset-task
  mismatch, confirmed with the project owner before training, not silently
  worked around), and it has **not** been evaluated against `docs/AI_ML.md`'s
  non-negotiable Fitzpatrick/Monk tone-balanced fairness requirement — the
  source dataset's own metadata has no skin-tone field. Not release-ready.
  Not wired into any endpoint. `metadata.json` in that directory has the full
  real metrics (per-class precision/recall/F1, confusion matrix, training
  history) — generated by the training run, never hand-written.

Every other M3 AI surface —
`IngredientSuitability` (rule-based), `Recommender` v2 (content-based weighted
formula), `ProgressTrendAnalyzer` (linear-trend + R²) — is deterministic, not a
trained model; `TextEmbedder`'s real implementation is a pinned, pretrained
SentenceTransformers checkpoint downloaded at runtime. Still nothing to
register for those, and won't be until:

- The optional flag-gated LightGBM ranker (`AI_IMPL_RECOMMENDER=ranker`,
  milestone_3.md §M3-D) is trained on real accumulated `recommendation_feedback`
  labels — deliberately not built yet since no real labels exist (`AGENTS.md` §0.2:
  never train on fabricated data).
- `SkinTypeClassifier`/`ConcernDetector`/`SkinScorePredictor` (still stubs, ADR-007)
  get real trained implementations matching their *actual* documented label
  spaces (cosmetic `skin_concerns`, not ISIC's lesion categories) in a future
  milestone.

**Shape** (matching `docs/AI_ML.md`'s model cards, and what `skin-lesion-
screener-0.1.0/` actually looks like):

```
ml/registry/
  {model}-{semver}/
    model.pt        # weights — gitignored, regenerate via ml/training/
    metadata.json   # training data slice, real metrics, fairness-gap status,
                     # training date, git commit — tracked
    README.md       # what this model is/isn't, intended use, disclaimers — tracked
```

Rollout stays per-model feature flags, M2-precedent canary at 10% of users before
100% (`docs/AI_ML.md` "Serving & ops") — no change to that plan here, just the
storage layout it uses. `skin-lesion-screener-0.1.0` isn't on that path yet —
it has no serving surface to roll out to (see its own README's "Why it isn't
wired into the backend yet").
